# 빌드 타임 CA 인증서

사내 프록시가 TLS 를 사내 CA 로 재서명하는 환경에서, **이미지 빌드 중에도**
패키지를 받아야 하므로 CA 가 필요하다.

사내 CA 파일(`*.crt`)을 이 디렉토리에 넣으면 Dockerfile 이 이미지의
신뢰 저장소에 등록한다.

```
certs/
  corp-root-ca.crt      <- 여기에
```

## 왜 디렉토리가 비어 있어도 유지되나

Dockerfile 의 `COPY certs/ ...` 는 디렉토리가 없으면 **빌드가 실패한다.**
인증서가 필요 없는 환경(로컬·GitHub)에서도 빌드가 되어야 하므로
`.gitkeep` 으로 디렉토리만 유지한다. 인증서가 없으면 등록할 것이 없을 뿐
빌드는 그대로 진행된다.

## 주의

- **인증서 파일은 커밋하지 않는다.** 루트 `.gitignore` 가 `certs/*.crt` 를 막는다.
  사내 CA 자체는 비밀이 아니지만, 사내 PKI 구조를 공개 저장소에 남길 이유가 없다.
- 확장자는 `.crt` 여야 한다. `update-ca-certificates` 는 다른 확장자를 무시한다.
  `.pem` 파일을 받았다면 이름만 `.crt` 로 바꾸면 된다 (형식은 같다).
- 런타임에는 필요 없다. 앱은 사내 패키지 저장소에 접속하지 않는다.
  런타임 TLS 가 필요해지면 그때는 파드 레벨에서 CA 를 마운트한다.

사내 CA 배포 경로는 `docs/open-questions.md` #43 참고.
